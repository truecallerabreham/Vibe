# Arc — Architecture Canvas

Design production-grade architectures by learning from real open-source projects.

```
arc build "multi-tenant saas with stripe integration"
```

Arc searches GitHub for architecturally relevant open-source repos, generates real architecture diagrams, and opens an interactive canvas where you can explore, compose, and get AI-powered reviews.

## Features

- **Real diagrams, not AI slop** — diagrams are generated by [GitDiagram](https://gitdiagram.com) from actual file trees and READMEs, not LLM hallucinations
- **Smart discovery** — LLM-powered queries find repos with the most similar architecture to your idea
- **Rich component detail** — click any component to see AI-generated analysis: purpose, trade-offs, alternatives, why it was chosen
- **Drag-and-drop canvas** — compose your own architecture by dragging components from reference diagrams
- **AI architecture review** — get structured feedback on your composed design: strengths, risks, and actionable suggestions
- **Multi-provider LLM** — supports OpenRouter, Groq, GLM, and Gemini

## Requirements

- Node.js 18+
- GitHub personal access token (for searching repos)
- LLM API key (one of: OpenRouter, Groq, GLM, or Gemini)

## Installation

```bash
npm install -g arc
```

Or run from source:

```bash

```

## Configuration

Set these environment variables or add them to `~/.arcrc`:

| Variable | Description |
|----------|-------------|
| `ARC_LLM_PROVIDER` | LLM provider: `openrouter`, `groq`, `glm`, `gemini` (default: `groq`) |
| `ARC_GROQ_KEY` | Groq API key |
| `ARC_GROQ_MODEL` | Groq model (default: `llama-3.3-70b-versatile`) |
| `ARC_OPENROUTER_KEY` | OpenRouter API key |
| `ARC_OPENROUTER_MODEL` | OpenRouter model (default: `deepseek/deepseek-chat`) |
| `ARC_GLM_KEY` | GLM (Zhipu AI) API key |
| `ARC_GLM_MODEL` | GLM model (default: `glm-4-flash`) |
| `ARC_GEMINI_KEY` | Google Gemini API key |
| `ARC_GEMINI_MODEL` | Gemini model (default: `gemini-2.0-flash`) |
| `GITHUB_TOKEN` | GitHub personal access token with repo scope |
| `ARC_GITDIAGRAM_URL` | GitDiagram instance URL (default: `http://localhost:3001`) |

### ~/.arcrc example

```yaml
llm_provider: groq
groq_key: gsk_...
openrouter_key: sk-or-v1-...
openrouter_model: deepseek/deepseek-chat
glm_key: ...
gemini_key: ...
```

## Usage

```bash
# Search repos, generate diagrams, and open the design canvas
arc build "customer support ai agent"

# Just discover relevant repos without opening the canvas
arc discover "video editor backend"

# Help
arc --help
```

### Example workflow

1. Run `arc build "real-time collaborative document editor"`
2. Arc searches GitHub for repos with similar architecture
3. If GitDiagram is running, real architecture diagrams are generated; otherwise, it falls back to LLM-based diagrams
4. A browser opens showing reference architectures as interactive node graphs
5. Click any component to see detailed analysis (purpose, trade-offs, alternatives)
6. Drag components onto the design canvas to compose your own architecture
7. Click "Review My Architecture" for AI-powered feedback

## How it works

```
CLI (commander) → GitHub Search → GitDiagram API / LLM → Local Web Server → React Flow Canvas
```

1. **Describe** your project idea
2. **Search** GitHub for the most architecturally relevant open-source repos (LLM-powered query generation + ranking)
3. **Diagram** each repo's architecture via GitDiagram backend or LLM fallback
4. **Explore** reference architectures in an interactive React Flow canvas
5. **Compose** by dragging components into your own design
6. **Analyze** components with AI-generated detail
7. **Review** your composed architecture with structured feedback

## GitDiagram Setup (optional)

For best diagram quality, run a local GitDiagram backend:

```bash
cd gitdiagram
cp .env.example .env
# Edit .env with your API keys
cd backend
uv sync
uv run uvicorn app.main:app --host 0.0.0.0 --port 3001
```

Arc automatically detects the backend and falls back to LLM diagrams if unavailable.
